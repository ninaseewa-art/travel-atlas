# ChatGPT Plus ↔ Наш атлас: разовая настройка

Это отдельный личный GPT с Actions. Он принимает скриншоты в ChatGPT, составляет готовые карточки и отправляет их в ваш атлас; читает места/коллекции и обновляет записи. OpenAI API не используется: отдельно платить за API не нужно. Действуют лимиты вашей подписки Plus и бесплатных квот Supabase. Не подключайте платный тариф или автоматическое увеличение расходов.

История обычных чатов ChatGPT не подключается. Изображение распознаёт ChatGPT; сервер получает готовый текст и координаты. Исходные скриншоты через Actions к карточке пока не прикрепляются. Приложение само не отправляет изображения или атлас в ChatGPT: данные поступают в него по вашим сообщениям и вызовам Actions.

## 1. Опубликуйте код

Объедините PR с подключением GPT в GitHub, дождитесь успешного Production deployment в Cloudflare. Откройте постоянный адрес https://travel-atlas-c9a.pages.dev/ и обновите приложение при появлении уведомления. В настройках появится раздел «Связь с ChatGPT Plus».

## 2. Добавьте SQL в свою базу

1. Откройте Supabase → проект **travel-atlas** → **SQL Editor** → **New query**.
2. Откройте файл [004_gpt_actions.sql](../supabase/migrations/004_gpt_actions.sql) в GitHub. Нажмите **Raw**, скопируйте весь SQL.
3. Вставьте SQL в новую вкладку SQL Editor и нажмите **Run**. Нужен успешный результат без ошибок. Это новая миграция; повторно запускать её после успешной установки не нужно.
4. Миграция использует уже существующие таблицы атласа. Она создаёт отдельный доступ GPT и не удаляет места.

## 3. Опубликуйте функцию Supabase — без терминала и новых ключей

1. В Supabase откройте **Edge Functions** в левом меню.
2. Выберите **Deploy a new function → Via Editor** (редактор функции).
3. Назовите функцию **atlas-gpt** — точно так, с дефисом.
4. Откройте [supabase/functions/atlas-gpt/index.ts](../supabase/functions/atlas-gpt/index.ts) → **Raw**. Скопируйте весь файл и замените им содержимое `index.ts` в редакторе Supabase.
5. Нажмите **Deploy function**.
6. В настройках опубликованной функции выключите проверку **Verify JWT / Verify JWT with legacy secret** и сохраните настройку. Это обязательный шаг: ключ Actions — отдельный ключ атласа, а не JWT Supabase. Сама функция проверяет этот ключ и отказывает любому запросу без него.
7. Адрес получится `https://ВАШ_PROJECT_REF.supabase.co/functions/v1/atlas-gpt`. Не добавляйте service_role или OpenAI API key. Функция использует стандартные `SUPABASE_URL` и `SUPABASE_ANON_KEY`, которые Supabase предоставляет автоматически.

Если работаете через CLI, эквивалент шага 3: `supabase functions deploy atlas-gpt --project-ref ВАШ_PROJECT_REF --no-verify-jwt`. Это альтернатива редактору, а не дополнительный обязательный шаг.

## 4. Получите персональный ключ и схему

1. Войдите в атлас своей приглашённой почтой. Откройте **Ещё / Настройки → Связь с ChatGPT Plus**.
2. Нажмите **Создать ключ подключения**. Ключ действует 90 дней и хранится в базе только в виде SHA-256 хеша. После закрытия настроек исходный ключ восстановить нельзя; можно выпустить новый.
3. Пока оставьте эту страницу открытой. Ключ понадобится в настройках Actions, **не в переписке**. Кнопка **Скопировать ключ** копирует его полностью.
4. Нажмите **Скачать схему Actions**. Откройте скачанный `atlas-gpt-openapi.json` в текстовом редакторе и скопируйте весь текст. В схеме уже указан адрес вашего Supabase; менять поля вручную не нужно.

## 5. Создайте личный GPT

1. На компьютере откройте https://chatgpt.com/gpts/editor (или ChatGPT → GPTs → Create / Создать).
2. Откройте вкладку **Configure / Настроить**. Название: **Мой атлас путешествий**.
3. В поле **Instructions / Инструкции** вставьте полный текст [gpt-instructions.txt](../public/gpt-instructions.txt) (GitHub → Raw → скопировать). Эта инструкция задаёт распознавание, поиск координат, описание, особенности, атмосферу и сохранение.
4. В **Capabilities / Возможности** включите **Web Search / Поиск в интернете**, чтобы GPT мог проверять официальные сведения, координаты, цены и даты. Не включайте дополнительные платные интеграции.
5. В разделе **Actions / Действия** нажмите **Create new action / Создать действие**.
6. В поле **Schema** вставьте текст скачанного `atlas-gpt-openapi.json`.
7. В **Authentication** выберите **API Key**, затем тип **Bearer**. В поле ключа вставьте ключ из атласа кнопкой «Скопировать ключ». Не добавляйте слово `Bearer` вручную, не используйте Supabase publishable/service_role и не вставляйте ключ в Instructions.
8. Сохраните Authentication. В списке должны появиться `searchAtlasPlaces`, `getAtlasPlace`, `saveAtlasPlace`, `listAtlasCollections`, `createAtlasCollection`.
9. Нажмите **Test** у `searchAtlasPlaces`. Подтвердите вызов, если ChatGPT спросит. Должен вернуться JSON со списком `places` (пустой список тоже нормален).
10. Сохраните GPT с доступом **Only me / Только я**. Этот API-ключ даёт чтение и изменение вашего атласа, поэтому GPT должен оставаться личным. Второй владелец может создать собственного личного GPT со своим ключом.

## 6. Использование

Откройте именно созданный GPT и отправьте скриншот с сообщением:

> Добавь этот замок в мой атлас. Сам найди точное место, опиши его особенности, атмосферу и что стоит знать перед поездкой. Если он уже есть, обнови карточку, сохрани мои заметки и коллекции.

GPT заполняет карточку сам. Если место определено однозначно и вы попросили добавить его, повторно переписывать поля не нужно. Если на изображении неясный объект, GPT задаст короткий уточняющий вопрос. Сама платформа ChatGPT может попросить разрешить запись через Action: нажмите подтверждение, чтобы запись была отправлена.

Сообщение «Сохранено» должно появляться только после ответа API с `saved: true`. Откройте атлас и проверьте новую карточку. Подписка приложения на Realtime обновит открытый атлас; при необходимости нажмите «Обновить данные» в его настройках.

Другие примеры:
- «Какие замки у меня уже сохранены в Германии?»
- «Покажи коллекции и добавь этот отель в “Италия”».
- «Поставь этому месту “Были”, личные заметки оставь».
- «Допиши атмосферу и практические советы к этому месту, проверь источники».

Субъективная атмосфера и возможные ощущения отделены от фактов. GPT не может гарантировать эмоциональное состояние. Проверяйте актуальные цены и условия у самой локации.

## Ошибки и отключение

- **401 / INVALID_TOKEN**: проверьте Bearer, создайте новый ключ в атласе и замените его в Authentication. Старый ключ немедленно перестаёт действовать при замене. После 90 дней нужен новый.
- **Invalid JWT** до ответа функции: в Supabase у функции ещё включён Verify JWT — выключите его. Не заменяйте личный ключ на service_role.
- **503 / MIGRATION_REQUIRED**: SQL шага 2 ещё не выполнен или схема PostgREST не обновилась. После успешного SQL подождите немного, повторите Test. Функция не должна выдавать «Сохранено» при ошибке.
- **404**: проверьте точное имя функции `atlas-gpt` и адрес сервера в схеме. Пути `/places` и `/collections` дописывает Actions.
- **409 / STALE_WRITE**: карточка была изменена параллельно. GPT должен перечитать её и сохранить ваши изменения, а не затереть их.
- **429**: лимит 60 успешных вызовов в минуту на ключ; подождите минуту. Квоты Supabase и Plus действуют отдельно.
- **Отключить**: атлас → Настройки → **Отключить доступ GPT**. Места остаются; ключ сразу перестаёт работать.

Эта настройка не требует раскрывать пароль или токен в переписке. Не присылайте скриншот экрана с открытым ключом.
