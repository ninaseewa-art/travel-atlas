# Наш атлас

Приватный атлас путешествий для двух владельцев. React 19 + TypeScript + Vite, Three.js / react-globe.gl, Leaflet, TanStack Query и Supabase. Русский интерфейс, 3D Земля с локальной текстурой NASA, адаптивный PWA для iPhone.

**Состояние:** MVP реализован в коде. Для вашего рабочего пространства нужно создать Supabase-проект и опубликовать сайт по инструкции ниже. Без настройки показывается экран подключения; демопросмотр запускается отдельно и не сохраняет данные. Демо не подменяет реальное хранение.

## Быстрый запуск

Требуется Node.js 24 LTS, npm 11. Платные API не нужны.

```sh
npm ci
cp .env.example .env.local
# Заполните два публичных параметра Supabase в .env.local
npm run dev
```

Рабочий каталог — корень репозитория. Vite выводит локальный адрес. После изменения `.env.local` перезапустите сервер. Без переменных можно открыть явный демопросмотр. Для реальных данных следуйте следующему разделу.

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run preview
```

## Настройка бесплатного Supabase: пошагово

1. Создайте проект в [Supabase](https://supabase.com/dashboard), **Free**, без платного апгрейда. Пароль БД сохраните в менеджере паролей; приложение его не использует.
2. В SQL Editor выполните **по порядку**, каждый файл один раз:
   - `supabase/migrations/001_atlas.sql`
   - `supabase/migrations/002_ordering.sql`
   - `supabase/migrations/003_validation.sql`
3. Скопируйте `supabase/provision.sql` в SQL Editor, замените `owner-one@example.com` и `owner-two@example.com` на два настоящих email **в нижнем регистре**, выполните. Создаётся одно пространство и десять пустых коллекций. Никаких демонстрационных мест в рабочую базу не добавляется. Повторный запуск намеренно запрещён.
4. Authentication → Sign In / Providers: включите Email и отключите **Allow new users to sign up** (публичную регистрацию). Даже если её случайно включат, сервер выдаст workspace только двум разрешённым подтверждённым email. В клиенте регистрации нет, magic link использует `shouldCreateUser: false`.
5. Создайте этих двух пользователей через Authentication → Users → Add user. Есть два варианта:
   - **Invite user:** письмо-приглашение. Сначала настройте Site URL / Redirect URLs (шаг 7), затем пригласите и примите ссылку. После первого подтверждения можно входить magic link.
   - **Create new user:** задайте каждому отдельный сильный пароль и включите Auto Confirm User, только убедившись, что это ваши два адреса. Передайте пароль владельцу лично, безопасным каналом. В приложении выберите вкладку «Пароль». Это практичный вариант без настройки SMTP.
6. В Connect / Project Settings → API найдите Project URL и **publishable key** (`sb_publishable_…`) либо legacy **anon** key. Заполните `.env.local`:
   ```dotenv
   VITE_SUPABASE_URL=https://your-project.supabase.co
   VITE_SUPABASE_ANON_KEY=your-public-publishable-or-anon-key
   ```
   Название переменной историческое: поддерживает оба типа публичного ключа. **Никогда не используйте `service_role` или `sb_secret_…` в VITE-переменных.** URL и публичный ключ присутствуют в сборке; защиту обеспечивают RLS и Auth.
7. Authentication → URL Configuration: Site URL — адрес опубликованного HTTPS-сайта; Redirect URLs — его точный корень, а для локальной разработки также `http://localhost:5173` и `http://127.0.0.1:5173`. Не добавляйте wildcard для чужих доменов. Для invite-письма задайте Redirect URL на тот же сайт, если панель предлагает это поле.
8. Перезапустите Vite / пересоберите хостинг. Войдите первым владельцем, добавьте место, перезагрузите страницу. Войдите вторым на другом устройстве — место должно появиться. Проверьте редактирование, фотографию и экспорт.
9. В Storage bucket `atlas-photos` должен оставаться **private**. Его создаёт миграция: JPEG/PNG/WebP, максимум 10 МБ. Не добавляйте public policies и не отключайте RLS.

**Почтовые ограничения:** встроенная почта Supabase ограничена по частоте и адресатам; без собственного SMTP отправка может быть доступна только адресам вашей команды проекта. Не считайте отсутствие письма ошибкой UI. Используйте вариант Create new user + пароль или отдельно настройте SMTP с подходящим бесплатным лимитом. Приложение не подключает почтовый сервис и не оплачивает его за вас. Не присылайте пароли и SMTP-ключи в чат.

Два email хранятся в закрытой таблице `allowed_members`, доступной только администратору БД. Клиент не может менять список, добавлять memberships или создавать третьего владельца. Чтобы заменить одного владельца, администратор удаляет его membership и запись allowed_members, отзывает его Auth-сессии/удаляет пользователя, затем добавляет новый email и приглашает пользователя. Это административная операция; UI приглашений намеренно не открыт.

## Бесплатная публикация

Рекомендуется Cloudflare Pages. Автоматической публикации из этого репозитория пока нет: нужны ваш аккаунт и выбор домена.

1. Сохраните код в своём GitHub-репозитории (через обычные commit/push).
2. Cloudflare → Workers & Pages → Create → **Pages** → Connect to Git → выберите репозиторий.
3. Framework: Vite; Build command: `npm run build`; Output directory: `dist`; Root directory: корень проекта; Node.js: 24 (`NODE_VERSION=24`).
4. В Environment variables для production задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` из шага 6. Секретный ключ сервера не нужен.
5. Выполните Deploy. Полученный домен `https://…pages.dev` добавьте в Supabase Site URL / Redirect URLs. После изменения build-переменных запускайте новый deploy.
6. Откройте сайт, войдите каждым владельцем и выполните чек-лист ниже. Страницы `/places` и `/collections` должны открываться и при прямом переходе: SPA fallback находится в `public/_redirects`.

Альтернатива — Vercel: Import Git Repository → Vite → те же переменные → Deploy. Маршруты и заголовки заданы в `vercel.json`. Учитывайте условия Vercel Hobby для личного некоммерческого использования. В Cloudflare заголовки задаёт `public/_headers`.

CSP разрешает только ваш сайт, Supabase (`*.supabase.co`) и стандартные тайлы OSM. При использовании своего Supabase-домена нужно отдельно добавить его HTTPS/WSS в `public/_headers` и `vercel.json`. Не заменяйте CSP на `*`. Локальный HTTP Supabase не подходит под production CSP: для него используется dev-сервер.

## Установка на iPhone

1. Откройте **опубликованный HTTPS-адрес в Safari**, не во встроенном браузере мессенджера.
2. Поделиться → «На экран “Домой”» → «Добавить».
3. Запустите иконку «Наш атлас» и войдите. В standalone-приложении Safari и установленного PWA сессии могут отличаться; пароль — наиболее простой вариант повторного входа. Magic link иногда открывается в обычном Safari, поэтому при необходимости используйте вход по паролю в самом PWA.
4. Землю вращайте одним пальцем, приближайте двумя. Если 3D недоступен, включится 2D. Карточка открывается снизу; закрывается стрелкой или Escape с внешней клавиатуры. Все места доступны и списком.
5. Для фото используйте JPEG/PNG/WebP. Если фото сохранено только в HEIC, экспортируйте/конвертируйте его в JPEG **на устройстве** перед загрузкой. Автоконвертации HEIC в MVP нет. Камера iPhone: Settings → Camera → Formats → Most Compatible для новых JPEG.

PWA кэширует только оболочку, локальные иконки, текстуру и контуры карты. Приватные API-ответы и фото service worker не кэширует. Офлайн-редактирование не реализовано: при потере сети запись блокируется или показывается ошибка; unsaved-форма не закрывается. Список может показывать уже загруженные записи, пока вкладка открыта. Удалите приложение/данные сайта на общем устройстве после выхода, если не хотите оставлять оболочку.

## Что входит в MVP

- Серверная проверка двух приглашённых подтверждённых email, одно приватное пространство, Auth magic link/пароль.
- Реальный CRUD в PostgreSQL; транзакционный RPC сохраняет место, связи тегов/коллекций и цену. `updated_at` используется для обнаружения конфликтов. Авторство создания защищено триггером.
- 24 категории, десять начальных коллекций, создание/переименование/удаление/порядок коллекций; удаление коллекции сохраняет места.
- Места в нескольких коллекциях, свободные нормализованные теги с подсказками, статусы, избранное, история дат посещения, личные заметки.
- Поиск, несколько значений фильтров по стране/региону/городу/категории/коллекции/тегу/сезону, статус, избранное и бюджет. AND между группами, OR внутри группы; бюджет сравнивается только в выбранной валюте, без конвертации. Последние фильтры сохраняются локально.
- Ручные координаты или клик на 2D-карте; проверка близких одноимённых дублей с подтверждением. Автоматического слияния нет.
- Несколько приватных фото, порядок и обложка, указание источника, удаление. EXIF не переносится при клиентском JPEG-перекодировании. Фото уменьшаются до 2400 px по длинной стороне.
- 3D с инерцией, pinch/zoom, маркерами, агрегацией, скрытием обратной стороны; клавиатурные стрелки и +/-; опция автовращения, пауза после взаимодействия, reduced motion. Выбор из списка фокусирует карту/глобус.
- Leaflet + OSM; при ошибке тайлов остаются локальные контуры Natural Earth. Это обзорная карта, без детальных улиц офлайн.
- Realtime с refetch, повторная загрузка при возврате во вкладку и раз в минуту. Удаления могут появляться с задержкой до минуты из-за ограничений фильтрации DELETE в Supabase Realtime. Нажмите «Обновить данные» для немедленного обновления.
- Экспорт всех записей в JSON, включая пути фото и метаданные. **Не содержит байты фото**: сохраняйте оригиналы отдельно через кнопку скачивания в карточке или администратором из Storage. JSON пока не восстанавливается через UI; импорт резервной копии и ZIP — следующие этапы.
- Цены — только введённые владельцем; источник, валюта, единица и дата проверки; не выдаются за текущие. Для отелей — за ночь. При отсутствии — «Не указана».

## Добавление места по скриншоту

1. Нажмите **«Добавить место» → «По скриншоту»**.
2. Выберите PNG, JPEG или WebP до 10 МБ. Если браузер умеет читать HEIC/HEIF, он также преобразуется локально; иначе экспортируйте в JPEG. Универсальный HEIC-декодер в приложение не включён.
3. Дождитесь OCR. Русский и английский текст распознаются Tesseract.js в Web Worker на устройстве. При первом использовании с вашего сайта загружаются статические worker/WASM и две языковые модели (несколько мегабайт). Само изображение не отправляется во внешние сервисы. Модели берутся из npm-пакетов с integrity в lockfile, а не со стороннего CDN во время распознавания.
4. Исправьте текст и выберите название. Цена и ссылка добавляются только по вашему выбору. Для неоднозначных `$`/`¥` нужно указать валюту. Цена со скриншота не считается актуальной: дата проверки остаётся пустой, источник можно уточнить в карточке.
5. При желании введите название/город и нажмите **«Найти»**. Только этот запрос отправится в публичный Nominatim / OpenStreetMap; полного OCR-текста и изображения в запросе нет. Автопоиска и autocomplete нет, повторные запросы ограничены и кэшируются в памяти. Выберите результат явно. Если поиска нет/он недоступен — задайте координаты вручную в следующем окне.
6. Нажмите **«Проверить карточку»**. Проверьте название, страну, категорию, цену, коллекции и координаты. Без выбора результата широта и долгота остаются пустыми; случайная точка не сохраняется. Фотография без читаемого текста не обеспечивает определения места — название и координаты вводятся вручную.
7. Нажмите **«Сохранить место»**. Данные записываются через существующий транзакционный RPC. Для обновления не требуется новая SQL-миграция.

По умолчанию скриншот и полный OCR-текст не сохраняются. Есть отдельные отметки для добавления текста в личные заметки и изображения в приватную карточку с подтверждением права использования. Изображение пересоздаётся без EXIF; при закрытии формы локальный preview освобождается, рабочий OCR-процесс останавливается. Ошибки OCR оставляют доступ к ручному вводу. Не загружайте весь пакет повторно при частичном сбое: если место сохранено, но фото не загрузилось, UI сообщает об этом и предлагает добавить фото через карточку.

В демопросмотре можно попробовать распознавание и проверить поля, сохранение отключено. Массовая очередь скриншотов, импорт URL и vision-распознавание фотографии без текста остаются следующими задачами. Платные AI-сервисы не подключены.

Статические OCR-ресурсы собираются командой `npm run prepare:ocr`, автоматически перед `dev`/`build`. Папка `public/ocr` генерируется и не коммитится; Web Worker bootstrap — `public/ocr-worker.js`. OCR-ресурсы не увеличивают обязательный PWA-precache. CSP разрешает компиляцию WebAssembly через `wasm-unsafe-eval`, без разрешения обычного `unsafe-eval`; production preview использует тот же CSP для проверок.

После новой публикации приложение показывает уведомление «Доступна новая версия атласа» с явным подтверждением обновления, чтобы не терять несохранённую форму. При первом переходе со старого MVP без такого уведомления закройте все вкладки сайта и откройте его заново либо используйте приватное окно.

## Архитектура

- `src/App.tsx`: вход, workspace, навигация `/`, `/places`, `/collections`, списки, карточка, фильтры, настройки.
- `src/World.tsx`: ленивый 3D-модуль, кластеризация, 2D fallback с локальными контурами.
- `src/Editor.tsx`, `src/Modal.tsx`: формы и доступные диалоги.
- `src/ScreenshotImport.tsx`, `src/ocr.ts`, `src/screenshot.ts`: локальный OCR, проверяемые кандидаты и явный поиск геолокации.
- `src/UpdatePrompt.tsx`: уведомление об обновлении PWA с подтверждением.
- `src/domain.ts`: типы, конфигурация категорий, Zod, чистые фильтры и нормализация.
- `src/api.ts`: Supabase-клиент, реальные операции, private signed URLs (1 час), загрузка с компенсацией ошибок, JSON-экспорт.
- `supabase/migrations`: таблицы, индексы, RLS, composite FK для защиты межпространственных связей, RPC.
- `public/ATTRIBUTION.txt`: источники и лицензии; текстура NASA и Natural Earth локальные. Геоданные, запросы и фото не отправляются в AI-сервисы.

Ссылка на карту открывает внешний OSM; карта запрашивает публичные тайлы, раскрывая провайдеру IP и область просмотра. 3D-глобус не требует стороннего картографического сервиса. Приватные signed URLs доступны любому, кому вы их передадите, до истечения часа — не публикуйте их. При массовом трафике стандартный сервер тайлов OSM не является неограниченным CDN; соблюдайте его [политику](https://operations.osmfoundation.org/policies/tiles/).

## Тестирование

```sh
npm test                  # чистая логика + настоящие SQL/RLS в PGlite
npm run typecheck
npm run lint
npm run build
npx playwright install chromium   # один раз, если системного Chromium нет
npm run test:e2e
npm run test:pwa          # production: manifest, SW и оболочка без сети
```

Браузерные тесты запускают отдельный Vite на 4173. По умолчанию используется `/usr/bin/chromium` в облачной среде. На обычной машине задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` или уберите `executablePath` в конфигурации, чтобы использовать установленный Playwright Chromium. `iphone` в конфигурации — **эмуляция размера/тача iPhone в Chromium, не Safari**. Реальный iOS Safari должен быть проверен на устройстве по чек-листу.

Для проверки настоящего Supabase (тестовый проект, не рабочие личные данные) подготовьте трёх подтверждённых пользователей. Первые два в allowed_members, третий — только в Auth и **без membership**. Публичная регистрация остаётся отключена. В приватном окружении задайте:

```text
ATLAS_TEST_URL
ATLAS_TEST_ANON_KEY
ATLAS_TEST_OWNER1_EMAIL
ATLAS_TEST_OWNER1_PASSWORD
ATLAS_TEST_OWNER2_EMAIL
ATLAS_TEST_OWNER2_PASSWORD
ATLAS_TEST_OUTSIDER_EMAIL
ATLAS_TEST_OUTSIDER_PASSWORD
```

```sh
npm run test:integration
```

Скрипт использует обычные пользовательские JWT, создаёт временное место/коллекции и фото, проверяет двух владельцев, постороннего/анонимного клиента, конфликт, Storage, удаление и очищает свои записи. Без параметров завершается с `NOT RUN` и кодом 2. Никогда не передавайте service-role key: он обходит RLS и делает эту проверку бессмысленной.

Для локального Supabase с Docker: `SUPABASE_USE_SLIM_IMAGES=true npx supabase start`, затем миграции применяются автоматически. Создайте пользователей через локальный admin API/Studio, выполните `provision.sql` с их email. `supabase/config.toml` предназначен **только для локальной разработки**; публичная регистрация там также выключена. В sandbox без записи в домашнюю папку используйте отдельный `SUPABASE_HOME=/tmp/atlas-supabase-home`. Данные Docker не отправляются в облачный проект. Для остановки: `npx supabase stop`.

Автоматическая live-проверка с временными пользователями (только локальный адрес, не production):

```sh
SUPABASE_HOME=/tmp/atlas-supabase-home SUPABASE_USE_SLIM_IMAGES=true npx supabase start
# Status содержит локальные серверные ключи: сохраните в приватный файл, не печатайте в лог.
umask 077
SUPABASE_HOME=/tmp/atlas-supabase-home npx supabase status -o json > /tmp/atlas-local-status.json
ATLAS_LOCAL_STATUS_FILE=/tmp/atlas-local-status.json npm run test:local
```

`test:local` создаёт временное пространство/двух владельцев/постороннего, запускает настоящий API/RLS/Storage-тест и два UI-сценария (desktop и мобильный Chromium), затем удаляет свои тестовые данные и пользователей. Не копируйте status JSON в репозиторий. В этой cloud-среде унаследованный HTTP-прокси мешает контейнерному BusyBox wget health-check (403), хотя прямой loopback-check `wget -Y off` и настоящие API проходят. Только для этого диагностированного локального случая использовался флаг `--ignore-health-check`; live-тест обязателен. На обычной машине сначала используйте стандартные health-check. Не отключайте TLS, подписи или RLS. Подробные результаты — в [TESTING.md](TESTING.md).

### Приёмка после публикации

- Первый владелец добавляет место, две коллекции, два тега и фото. После reload данные остаются.
- Второй видит запись, меняет её, отмечает посещение; первый видит изменение. Проверить конфликт в двух открытых редакторах.
- Фильтр «Замки» одинаково влияет на глобус, 2D и список; сброс восстанавливает всё.
- Третий подтверждённый тестовый пользователь получает отказ, не может читать/писать таблицы, перечислять или скачивать фото по прямому API. Выполните live integration в тестовом проекте.
- На iPhone проверить поворот/масштаб Земли, карточку, выбор фото, клавиатуру без увеличения страницы, standalone-вход, безопасные области и оба положения экрана.
- Отключить WebGL/тайлы — места доступны на базовой карте и в списке. Отключить сеть во время сохранения — форма показывает ошибку, без ложного «сохранено».
- Проверить удаление с подтверждением, экспорт JSON и скачивание фото.

## Ограничения и бесплатные лимиты

Следующие задачи этапов 2/3: универсальная HEIC-конвертация, URL-импорт, массовая очередь скриншотов, календарь/редактор событий, маршруты, ZIP/import backup, полноценное офлайн-редактирование, пользовательский рейтинг. Таблицы events/imports защищены RLS и зарезервированы; события не выданы за физические места. Нет рельефа/3D-зданий и платных спутниковых тайлов. Детальная 2D-карта включается кнопкой, автоматически при отсутствии WebGL, но не автоматически при зуме до улицы. Карта остаётся доступной через переключатель.

Supabase Free имеет квоты БД, Storage, трафика, активных пользователей, Realtime и функций; неактивные бесплатные проекты могут приостанавливаться. Cloudflare Pages и Vercel также имеют лимиты сборок/трафика и условия использования. Конкретные квоты меняются: перед публикацией проверьте [Supabase Pricing](https://supabase.com/pricing), [Cloudflare Pages limits](https://developers.cloudflare.com/pages/platform/limits/) и [Vercel limits](https://vercel.com/docs/limits). Бесплатность гарантировать при превышении лимитов нельзя. Ограничение фото 10 МБ и уменьшение изображения помогают расходу Storage. Автопереход на платный тариф не настраивается. Регулярно экспортируйте JSON и сохраняйте фото отдельно.

Если удаление фото/места прошло в БД, а очистка Storage упала, UI сообщает об этом: файл останется приватным до ручной очистки Storage. Если последовательная загрузка нескольких фото оборвётся, уже загруженные остаются, остальные нужно загрузить повторно. Не повторяйте весь пакет вслепую. Вложенные сущности самого места сохраняются атомарно.
