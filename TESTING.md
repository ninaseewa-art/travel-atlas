Live-проверка использовала настоящий локальный Supabase в Docker, с миграциями из репозитория, Auth/PostgREST/Storage/Realtime, обычными пользовательскими JWT и временным отдельным workspace. Временные пользователи и данные удалены после проверки. Дополнительно проверены обновление уже открытой карточки у второго владельца без reload, ошибка сетевого сохранения с сохранением формы и успешный повтор, а также скачанный JSON с местами, фото-метаданными, категориями и memberships. Service-role применялся **только в локальном тестовом fixture** для создания/очистки пользователей, не в приложении и не для проверки RLS.

Обнаружены и исправлены: отсутствующее доступное имя мобильной кнопки добавления; неоднозначные доступные имена select; преобразование пустой координаты в ноль; поддержка object/array формата вложенной цены PostgREST; обновление данных после частичной ошибки загрузки фото. После исправлений соответствующие live-сценарии прошли повторно.

## Ограничения доказательств

- Публикация в аккаунт владельца не выполнялась; облачный Supabase владельца не подключён. Требуются действия из README. Работа в новом опубликованном окружении не заявляется как проверенная.
- Мобильный Chromium с viewport/touch iPhone — не настоящий iOS Safari. Аппаратное устройство, standalone-вход и поведение magic link на iOS проверяются владельцами по README.
- SMS, SMTP-доставка, платные тарифы и сценарии этапов 2/3 не тестировались и не подключались.
- Сборка предупреждает о размере ленивого 3D-модуля: около 1.95 МБ minified / 0.55 МБ gzip. Базовая оболочка и 2D не зависят от успешного WebGL; первая загрузка 3D на медленной сети требует времени.
- В этой cloud-среде контейнерный BusyBox wget отправляет health-check через унаследованный HTTP-прокси и получает 403. Прямой loopback-check `wget -Y off` вернул 0; настоящие API и браузерные сценарии прошли. Для этого диагностированного локального случая стек запускался с `--ignore-health-check`. Проверки RLS, TLS и целостности образов не отключались. Docker-образы использовали проверенные registry digest/checksum. На обычном компьютере сначала используйте стандартные health-check.
